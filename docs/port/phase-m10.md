# Phase M10: the scsynth crash with twins, a dead server, long names under [ext] (Windows 0.10.1)

Report of the owner on 0.10.0: with the script twins, `sclang.log` says "Server 'localhost' exited with exit code -1073741819" (0xC0000005) after a sample was loaded; no sound; the next script waited for ever ("still waiting for engine Autumn") until a restart; norns.log has "Tape Reader:: cannot open sndfile" for long names under an [ext] folder, the name cut with "...".

## 1. What was measured (CI, a real Windows runner, `m10-*` checks of windows/ci/smoke-m1.sh)
- The REAL `lib/engine_twins.sc` (twins cloned at a pinned commit), the real scsynth with the plug-in paths of the launcher (PortedPlugins pack included), the script resumed through norns's state, a wav made in CI given to both voices through the script's own parameter (`params:set("1sample", ...)` = `engine.read`), the server asked every 10 s for 40 s.
- Result: the engine loads (145 commands), both samples load, **the server lives, no crash, no minidump**. Scenarios run (each 250 s): the first one (48 kHz clock, 3 s stereo 16 bit wav), the server at 44.1 kHz with a 20 s stereo 24 bit wav, at 96 kHz with an 8 s mono wav, and the sample as a file with a 126 character name under an [ext] link (total path over 260 characters).
- Not measured, because a runner has none: a real sound device (real-time callback with a WASAPI device, its own sample rate and block size), the owner's own sample files and parameter changes by hand.
- The bisect by UGen (taking AnalogChew, AnalogLoss, AnalogDegrade out of a copy of the engine one by one), the WER minidump and its reader (`windows/ci/dump_report.py`) are in place and run only when a scenario dies. None did, so there is no module, offset or stack to report. **The cause of the owner's crash is not found and nothing was changed for it.**
- (An earlier run showed "exit code 1" 3 s after every start and the launcher restarted every round: the run with identical product code right after had none; that run and the old-checks "only log" mode are in the history of this phase. Cause not established; one more run of the older M0 workflow showed `scsynth` exit code 1 once too, so it may be the runner. The watch is in log-only mode for the older checks since.)

## 2. What changed (all of it tested)
- **A dead server is noticed** (`windows/launcher/server_watch.h`, `verdandi.c`): the launcher reads sclang.log once a second for sclang's line "Server 'localhost' exited with exit code N." (exit code 0 is a normal end). A stop answers with: a line in launcher.log (code in hex), a plain one-line note on the norns screen (the note file `<home>\.verdandi-note`, shown by `lua/core/menu.lua`), a restart of the whole round (norns asks itself through the existing `.norns-request-restart`, ended by force after 20 s): norns.exe, sclang and scsynth start again and the script resumes with its engine. Twice in a row; the third stop in a row says "SuperCollider keeps stopping ... not restarting it again", and norns stays up. A round that ran 10 minutes without a stop starts the count again. Test: scsynth.exe is ended from outside three times (`PROBE kill-*`): restart, restart, message, no round 4, norns still answers.
- **A loading screen never waits for ever for a dead server** (`lua/core/engine_fail.lua`, `script.lua`): while a script waits for its engine the log is read; the server's exit line stops the load at once with "SuperCollider stopped (error 0xC0000005)" on the screen and in the log. `linux/tests/engine_fail_test.lua`.
- **Long names under [ext]**: two causes. (a) `lua/lib/fileselect.lua`: the preview (E3) and the selection (K3) used the text of the row, which is cut with "..." for a long name ("cannot open sndfile ...sampl...."), and they used the position in the list of ALL files although the filter hides some: K3 could pick the wrong file. Both use the real name now (`linux/tests/fileselect_longname_test.lua` fails on the old code). (b) the sound-file opens of matron and crone (`audio.file_info`, the Tape Reader, buffer reads and writes) took the narrow ANSI path and the 260 character limit of Windows; `crone/src/sf_path.h` makes the path wide, absolute, with `\\?\` when long (sf_wchar_open); Linux and macOS are unchanged. CI: a wav with a 126 character name under an [ext] link (237 characters of virtual path, 260 and more of real path): `audio.file_info` reads it and the Tape Reader has no "cannot open sndfile". (It was not shown that (b) failed before: an earlier probe of mine was wrong.)

## 3. What is not known
The cause of the owner's crash. Next measurements, if it comes back: the launcher.log line now names the exit code; Windows's own crash dump of scsynth.exe (WER LocalDumps needs administrator rights: the owner can switch it on, windows/ci/dump_report.py reads the dump); a scsynth crash reporter like norns.exe's (`crash_report_win.cc`) as a patch of SuperCollider would name the plug-in module without the owner doing anything: not built, waiting for the owner's OK.
