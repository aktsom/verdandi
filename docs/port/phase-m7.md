# Phase M7: SuperCollider plug-in packs for Windows (sc3-plugins, mi-UGens, NamAmp)

Status: **built in CI (all green); not yet tried on a real Windows PC.** Results in section 6.

## 1. Why
A script whose engine uses a UGen that the Windows build lacks (owner test of 0.7.0: engine Autumn needs `Decimator`) cannot start. On Linux and on the device these UGens come with the system packages / the norns image. On Windows nothing provides them, so the build ships them.

## 2. What is shipped (owner decision)
- **The whole sc3-plugins collection** (https://github.com/supercollider/sc3-plugins, GPL-2.0-or-later; a few directories carry other free licences, their files are copied to `licenses\sc3-plugins\`), built for Windows x86-64 with MSVC against the headers of SuperCollider 3.14.1. Every plug-in directory is built on its own (`ninja -k 0`), so a directory that does not compile never blocks the others. What builds ships; what does not is listed in `extensions-seed\BUILD-REPORT.txt` and in section 6 with the first error and what it would need (an extra library, a POSIX-only call, ...).
- **mi-UGens** (https://github.com/v7b1/mi-UGens, MIT code of Emilie Gillet and v7b1's GPL-3.0-compatible parts; its licence files are copied), built the same way. (A Windows release zip exists upstream, but some releases carry empty `Classes` folders; building ourselves gives a matching ABI and classes.)
- **NamAmp**: **not built yet.** I could not identify the repository that defines the NamAmp UGen (a search finds the Neural Amp Modeler project and VST3 plug-ins, no SuperCollider UGen). The job builds it as soon as the CI variable `NAMAMP_URL` (Settings > Secrets and variables > Actions > Variables) names the git URL. It also needs: the licence of that code, and whether it needs the NAM core library or a model file (`.nam`) shipped.

## 3. How it gets to the user (the M6 seed mechanism, unchanged)
`windows/ci/build-sc3plugins.sh` (job `plugins`, not blocking) writes `seed/<pack>/` with `plugins\*.scx` and the class files. `assemble-m1.sh` copies each pack that has at least one `.scx` to `extensions-seed\<pack>`; the launcher copies it to `<home>\extensions\<pack>` at the next start when the folder is not there yet, and never overwrites (so a user's own newer copy wins). The plug-in heal of M6 keeps non-x64 files out. Licence texts go to `licenses\<pack>\`; `SOURCE-OFFER.txt` of the zip names each repository and the exact commit (the `SOURCE-REVISION.txt` of the pack) as the written offer of the corresponding source.

## 4. The start-up check and the failed engine
- `lua/core/sc_class_check.lua` (read only, reads the end of `logs\sclang.log`) now also runs on Windows (extensions folder `<home>\extensions`) and reads `Class Decimator not found` as well as the quoted form. At start-up norns prints each finding and ONE line naming all missing classes: `SuperCollider classes missing: Decimator (sc3-plugins or another extension), ...; engines that use them will not start`.
- `lua/core/engine_fail.lua` (owner request 2): while a script waits for its engine the log is read from where it was at the start of the load; when sclang prints the error trace of `Engine_<name>:alloc` the load stops within a second, the log gets `engine Autumn failed: class Decimator is missing; this needs sc3-plugins`, the norns screen (and so the window) shows the same in five short lines until a key is pressed, and the next script loads normally. Test with a fake failing engine: `linux/tests/engine_fail_test.lua`.

## 5. Effort, risks, what is needed from the owner
- Effort after the first CI report: small if most of sc3-plugins compiles (the packs are just copied); for each directory that fails, one fix or one entry on the list of exclusions with the reason. Parts that typically need more: those using POSIX-only headers or large external libraries (for example the ones with `fftw`, `libsamplerate`, `libusb`); each is judged from the CI log, not guessed.
- Zip size: see section 6 (measured by the job, "all packs zipped").
- Licence obligations: the notices and source offers are in the zip as above. GPL-2.0-or-later code combined in one folder with GPL-3.0 Verdandi is compatible (it stays a separate program loaded by scsynth).
- Needed from the owner: (a) the git URL of NamAmp and its licence (set `NAMAMP_URL`), (b) after the first run, a look at section 6 to say whether any not-built part matters to the scripts in use, (c) on a Windows PC: install a script that needs Decimator (for example the one whose engine Autumn failed) and send `logs\sclang.log` and `norns.log`.

## 7. Round 2 (version 0.8.1): the mi-UGens pack had no class files; a failing extension took the whole start-up down
Owner report: `extensions-seed\mi-UGens` held `plugins\MiPlaits.scx` and no class files; a script whose engine uses `MiPlaits.ar` stopped with "Class 'MiPlaits' not found" inside `Meta_Emplaitress:initClass`, sclang's start-up aborted, no server booted, norns showed SUPERCOLLIDER FAIL.

1. **Cause.** Not the "duplicate Class found" fix. `build-sc3plugins.sh` looked for the mi-UGens classes in `Classes\` at the top of the repository, which does not exist: the repository keeps them in `sc\Classes\` (12 files, one per UGen, the plug-ins' sources are in `projects\`). The pack therefore never had a class file, in any build; CI could not tell, because it only checked that sclang started and nothing used a mi-UGens UGen. The script now copies `sc\Classes\*.sc` (12 files) and the licences (GPL-3.0 text, the MIT licence of the Mutable Instruments code in `eurorack\LICENSE.txt`, the readme). The duplicate-class check is kept and is now exact: comments are stripped before class names are counted (the earlier warning was a false positive: classes that appear twice inside a block comment), one file at a time (a file without a final newline must not glue to the next).
2. **sc3-plugins, plug-in files against classes.** The build now writes `UNITS.txt` (the UGen names its plug-in files define, taken from `DefineSimpleUnit(Name)` and its variants and the string form in the sources) into every pack and compares them with the classes of the pack and of SuperCollider's own library. Result for sc3-plugins Version-3.13.0 (checked here against the real sources): 418 UGen names; the classes of the 227 shipped class files cover all but about 60 names. Those are (a) the ATK units `Foa*` (their classes belong to the ATK quark, not to sc3-plugins), (b) helper units of the Josh and Stk plug-ins that no class of sc3-plugins calls by that name (for example `CubicDelay`, `Xover2`, `Sflute`, `StkSitar`), and a few more. None of the UGens that sc3-plugins documents lacks its class. The CI run prints the exact list (`m7-report.txt`, "UGENS WITHOUT A CLASS") and sclang prints it at every start (below).
3. **Pack refresh.** Every pack of the seed carries `PACK-ID.txt` (`<revision of its sources>-L<layout>`). The launcher now: copies a pack that is not in `<home>\extensions`; keeps an installed pack whose marker is the same; for another marker, or for the pack of the first release (our 0.8.0 layout: `SOURCE-REVISION.txt` and `plugins\`, no marker) it **moves the old folder to `<home>\disabled\<pack>-replaced`** (never deleted, restorable, one line in `launcher.log` and a number suffix if the name is taken) and copies the new one. Any other folder of `extensions` is never looked at, and a folder of the same name without our marker and without our files is the user's own and kept. A pack without `PACK-ID.txt` (no plug-in files, no class files, or a class twice) is not put into the zip. Rules: `windows/launcher/pack_refresh.h`, test `linux/tests/pack_refresh_test.c`.
4. **Tests that would have caught it.** (a) The CI headless start now builds real SynthDefs through the sclang console: `MiPlaits.ar`, `MiBraids.ar` (mi-UGens) and `Decimator.ar` (sc3-plugins), and adds one to crone's server and waits for `s.sync` (the job fails when a class is missing or the server does not answer: probes `repl-ugens`, `repl-server`). (b) The same step fails on "Class ... not found", "duplicate Class found" or an initClass failure in `sclang.log`, and checks that the packs, their class files, markers and the replacement of an older copy happened (check `m7-check-packs`; an old-layout `mi-UGens` and an own folder `MyOwnExt` are put in the test home first). (c) At every start sclang prints one line `### plug-in packs: N UGens have no class in sclang: ...` (or "every UGen of the packs has its class"), from `sc/desktop-safe/VerdandiPackCheck.sc`, which reads each pack's `UNITS.txt` after the class library is compiled (the full list: `logs\pack-check.txt`). It asks sclang itself whether a class of that name exists, so a class from another quark counts as known. The build report has the same check on the sources (`pack_check_test.sh` runs it on fixtures, including the mi-UGens pack without classes).
5. **Start-up robustness: feasible, without patching SuperCollider.** sclang's `Class.initClassTree` calls every class's `initClass` without a guard, so one failing `initClass` leaves `Process.startup` before the StartUp callbacks run (crone's start is one of them). `sc/desktop-safe/VerdandiSafeInit.sc` overrides `Class.initClassTree` (an ordinary class extension, SuperCollider reports "1 more method overwritten by extensions") with the same code plus a `try` around `initClass`: a failing class is named in one log line (`### initClass of Emplaitress failed, start-up goes on: ...`), the tree goes on, the StartUp callbacks run, crone and the server boot. Proven with the real sclang here (`linux/tests/safe_init_test.sh`: the failure reproduced without the file, gone with it). The folder is named `desktop-safe` because sclang skips folders named after a platform it is not running on (`windows` would not compile on Linux, and `linux` is skipped on Windows). Limit: a class whose `initClass` failed is only half initialised; what uses it can fail later with its own error. Another extension that also overrides `Class.initClassTree` would win or lose by folder order.
