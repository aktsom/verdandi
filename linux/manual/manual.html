Quick start

Install. Ubuntu 24.04 and Linux Mint 22 (amd64): sudo apt install ./verdandi_*.deb. That adds Verdandi Linux to the application menu and a verdandi command. To build it yourself, see docs/port/RUN-ON-LAPTOP.md. To update, install the newer package the same way.

First run. Start it from the application menu (or run verdandi). A window opens with the norns screen, three keys and three encoders. Your files live in ~/Verdandi (scripts and audio in ~/Verdandi/dust); nothing is written anywhere else. Sound goes to the desktop’s default card (PipeWire or JACK). To try it without sound: NORNS_JACK_DRIVER=dummy verdandi.

The five things everyone needs

  1. Keys. 1 2 3 are K1 K2 K3; QW AS ZX turn E1 E2 E3 left and right (Shift = 5 steps). F1–F4 open MIX, TAPE, HOME and PARAMS; F5 opens and closes the menu. Or click and drag with the mouse.
  2. A script. HOME > SELECT lists what is in ~/Verdandi/dust/code. Put scripts there, drop files on the window, or install from the catalog with the MAIDEN button.
  3. Sound in. The MIC button cycles MIC (the card’s input), SYS (every other application) and OFF.
  4. Everything else is one right-click away. The right-click menu (or F10) holds import, screenshot, GIF, mute and the virtual grid, arc and keyboard (F6 F7 F8). The look of the screen and the box is HOME > SYSTEM > SCREEN and THEME.
  5. If it does not work, read If something goes wrong: the logs are in ~/Verdandi/logs.

The window

The window is the norns screen on a drawing of the device. Resize it as you like; closing it ends norns. Mouse: click a key to press it, drag a knob (up or right turns it clockwise) or scroll over it; the wheel elsewhere turns the nearest knob.

button (above the device)does
MIX, TAPE, HOME, PARAMSopen that menu page; clicking the page that is up goes back to the script
MICinput: MIC, then SYS, then OFF (see Sound, MIDI and grids)
GRID, ARC, KEYSopen or close the virtual grid, arc and keyboard windows

The output level is on the MIX page (E2) and under PARAMS > EDIT > LEVELS. Hide the row of buttons with the right-click item “Show the page buttons”; the keys keep working, and a small MUTE button stays while muted.

The screen in its own window

F9 (or the menu item “Screen in its own window”) pops the screen out into a second window with only the picture, live, with the look of SYSTEM > SCREEN. F11 or a double click makes it fullscreen; Shift+F11 takes its title bar away (then drag the picture to move the window, its edges to resize it). Size, place, fullscreen and frame are remembered. The box shows a panel while the screen is out: click it, press F9, or close the screen window to bring the screen back. The keyboard works in both windows. Closing the main window quits norns.

Quitends norns

Scripts that read the keyboard themselves get the keyboard; for them Alt plus the keys of the quick start still works as K and E, and Alt+Esc switches that on and off. verdandi scan-fkeys lists scripts of yours that use keys Verdandi takes (F9, F11, Ctrl+M, the arc keys).

HOME: scripts and maiden

HOME has SELECT (choose a script), SYSTEM and SLEEP (quits norns; it does not power off the computer). Scripts live in dust/code/<name>/<name>.lua. Scripts see the device’s paths (/home/we/...); Verdandi maps them to your folder.

maiden is the web editor and script catalog: it opens at http://127.0.0.1:5000/maiden with the MAIDEN button, shows the files of dust, the norns and SuperCollider consoles, and installs and updates scripts. It answers on your own computer only. If port 5000 is taken, start with NORNS_MAIDEN_PORT=5001 verdandi.

Mods are folders dust/code/<name>/ with a lib/mod.lua; enable them under SYSTEM > MODS and restart. Commands a script runs through sudo systemctl restart norns-... are answered by restarting norns; other sudo commands fail at once instead of asking for a password.

mi-UGens (the Mutable Instruments sound engines that Emplaitress, Terrarium, oomph, fx_miUGens and others use) ships with Verdandi, built for your PC. When norns starts it copies the pack into ~/Verdandi/.local/share/SuperCollider/Extensions/mi-UGens if that folder is not there yet, so there is nothing to download or install: install the script, enable the mod if it is one, restart once. Scripts that look for the pack find it; the K3 “download + install” of Terrarium is not needed (do not use it: it fetches a pack for the Raspberry Pi that a PC cannot load). Verdandi never overwrites a folder that is not its own, a copy you changed, or a pack you added yourself: if another Mi*.sc file is already in the extension folders or in dust/code it copies nothing and says why in logs/launcher.log. A newer Verdandi package replaces only its own untouched older copy. SYSTEM > CLEAN UP has a line MI-UGENS that reads mi-UGens: <commit>, shipped with Verdandi <version> (commit of the upstream source, then the Verdandi version). Nothing is checked online. mi_ugens=0 in audio.conf (or NORNS_MI_UGENS=0) turns the copying off.

SYSTEM pages

HOME > SYSTEM lists, in this order: DEVICES, AUDIO, MODS, SCREEN, THEME, MIDI MAP, CLEAN UP, RESET, RESTART. WIFI, UPDATE and the password are left to the operating system. On every page E2 chooses a row, E3 changes it, K3 opens or acts, K2 goes back. Changes show at once and are kept.

SYSTEM > DEVICES

The MIDI, grid, arc and HID devices norns sees, and the keyboard layout. MIDI shows how many ports are auto-linked (see Sound, MIDI and grids). While serialosc is running with a grid plugged in, a SERIALOSC entry appears with the short guide (see If something goes wrong).

SYSTEM > AUDIO

Shows what is connected: INPUT, OUTPUT, RATE, BUFFER. With PipeWire the system owns card and rate; BUFFER is only a request PipeWire may refuse. With norns’s own jackd the rows change the devices, rate and period, and APPLY restarts norns. With a JACK server you started yourself the page is read-only.

SYSTEM > MODS

Every mod found in dust/code. E3 right enables, left disables; restart norns (SYSTEM > RESTART) to load or unload. A mod with an error is skipped and named in the log; the rest still load.

SYSTEM > SCREEN

How the screen looks in the window; a bar of the 16 grey levels shows the result.

COLOURK3 opens the colour picker with live preview; Ctrl+C copies the code, Ctrl+V pastes one

SYSTEM > MIDI MAP

Maps knobs, encoders and buttons of a MIDI controller to E1–E3, K1–K3, the four encoders of the virtual arc, and the buttons of the window. The window shows the control moving. Scripts are never touched: every message still reaches them; if the script’s own params MAP uses the same CC, it wins (ON CLASH = BOTH lets both react).

rowdoes
PRESETNONE, PUSH 2 (UNVERIFIED), GENERIC REL 2S, then your own (*); a preset sets the mappings for any device
LEARNK3, click a control in the window (E1–E3, K1–K3), then move the knob or press the button. An encoder asks you to turn it both ways to suggest its format. 15 seconds of silence or K2 cancels

A1–A4, GAIN, ACCEL, ONE TURNthe virtual arc’s encoders (turn the arc with 5 6, T Y, G H, B N; Shift = smaller steps). GAIN is ticks per MIDI unit; ONE TURN sets it from one full turn of your encoder. Needs the arc window open (F8)
WATCHturn an encoder a click each way: shows the values and which format it sends
ARC KEYSswitches the arc keys of the norns window on or off
ACTIONSmaps pads, buttons or encoders to MIX, TAPE, HOME, PARAMS, INPUT, GRID, ARC, KEYS, MAIDEN, MANUAL, MUTE, DETACH, FULLSCREEN, SCREENSHOT. K3 on an action learns it (press the pad); ASSIGN ALL walks through all of them; E3 right opens an action’s view, left clears it. Only a press acts; the same action does not fire twice within 0.25 s

Learning a note or CC that another control already uses asks first (“NOTE 36 IS MANUAL. MOVE IT TO MUTE?”). While a text entry is open your mapped E2, E3, K3 and K2 drive it like the keyboard does (that is how you can name a recording from a controller); everything else, actions included, is ignored.

SYSTEM > CLEAN UP

Shows what Verdandi keeps in your folder (disabled files, logs, crash reports, seeded packs, cache), each with its size. SEEDED counts the packs Verdandi copied into your SuperCollider extension folder (the mi-UGens pack; K3 lists them); the age rule below never removes the mi-UGens pack, which is in use. K3 opens a group; nothing changes without a second K3. An ARM PLUG-INS line appears when plug-ins built for the Raspberry Pi would stop SuperCollider: K3 K3 moves them to disabled/ (restorable from there). A CLASSES line appears when SuperCollider found the same class in two folders (for example two copies of mi-UGens): K3 K3 moves the copy that is not Verdandi’s to disabled/. The MI-UGENS line shows the commit of the mi-UGens Verdandi shipped; K3 on it opens a detail view with the whole line (shipped with Verdandi <version>) and the build date. Rows are cut with .. when a name is wider than the screen. The last line, REMOVE >N DAYS (30, 90, 180 or 365), is the only thing that deletes, after one confirmation. It never touches dust/ or your settings. The same from a terminal: verdandi tidy list.

SYSTEM > RESET

One question (K3 yes, K2 no): clears the norns system settings (the system preset and state, favourites, the list of enabled mods) and restarts. Your scripts, dust and the SCREEN, THEME, MIDI MAP and audio settings are not touched.

SYSTEM > RESTART

One question, then norns restarts (the window closes and opens again).

Sound, MIDI and grids

Sound. norns uses JACK. The launcher takes a JACK server that is already running; otherwise, if PipeWire runs, it uses it through pw-jack; otherwise it starts its own jackd. Under PipeWire norns plays to the desktop’s default output and listens to its default input, read when norns starts. To pin a card put out_ports= / in_ports= (the start of the client name pw-jack jack_lsp shows) in audio.conf. If no card is found norns starts unconnected and the window says “AUDIO: not connected, see SYSTEM > AUDIO”.

MIC button / Input menuwhat norns hears
MICthe input of the card norns chose
SYSthe sound of every application except norns (each appears as a JACK client; later ones join by themselves). norns’s own output is never in it, so it cannot feed back
one applicationchosen in the right-click menu
OFFnothing

With MIC on and speakers a script that plays its input can feed back: keep the volume low or use headphones. The choice is kept for the next start.

MIDI and a DAW. Real MIDI devices, grids, arcs and crow work over USB. The KEYS window is a MIDI device named “norns keys” (also an ALSA port where available). norns has one more MIDI device, virtual (in the device list, and usually vport 1), with two JACK MIDI ports: Verdandi:midi_in, which brings your DAW’s clock, start, stop, position and notes to norns, and Verdandi:midi_out, which carries whatever a script sends to the virtual device (m:note_on, m:cc, m:send, clock, start, stop …) to the DAW or a synth. Connect them with a patchbay or pw-jack jack_connect: your DAW’s MIDI output to Verdandi:midi_in (and set clock_source to midi in PARAMS > CLOCK to follow its clock), Verdandi:midi_out to a MIDI track’s input. To link ports automatically put midi_in_from= and midi_out_to= in audio.conf (the start of a JACK port name; several separated by ;, * for a changing number); both are off by default. Nothing is sent to Verdandi:midi_out unless a script sends it, and a script can send with nothing connected.

A DAW that reads ALSA MIDI only (Reaper on Linux and others) needs no bridge: the same messages also come out of a native ALSA MIDI port, Verdandi out (client “Verdandi”), which such a DAW lists as a MIDI input device (in Reaper: Preferences > Audio > MIDI Inputs; enable it, and arm a track on it). It carries what a script sends to the virtual device, every message type including clock, start, stop and sysex, in order. Nothing is connected by itself, and nothing is sent when no script sends anything. It is on by default; alsa_midi=0 in audio.conf (or NORNS_ALSA_MIDI=0) turns it off. There is no ALSA input port: a DAW’s clock and notes reach norns through Verdandi:midi_in. If the computer has no ALSA sequencer, norns says so in logs/norns.log and goes on without the port. There is no plug-in (VST3) version yet.

Reaper (and other DAWs that list only raw hw: MIDI devices, not sequencer ports) cannot see “Verdandi out” itself: it needs a bridge, the kernel’s virtual MIDI card (the module snd-virmidi). Put alsa_midi_out_to=VirMIDI in audio.conf (or set NORNS_ALSA_MIDI_OUT_TO) and restart norns: it connects Verdandi out to the ALSA port whose name starts with that text when the port appears and again after it is cut (it looks every 3 seconds). Nothing else is connected: not norns’s own ports, not your controllers, not Midi Through, unless the text names them; it is off without the line. If the module is not loaded the window says so, and HOME > SYSTEM > DEVICES > VIRMIDI loads it without a terminal: K3 asks once, then the desktop may open its own password dialog; if that cannot be done the page shows the command sudo modprobe snd-virmidi midi_devs=1. The page and the note also name the entry to enable in Reaper.

  1. In Reaper open Preferences > Audio > MIDI Devices and press Reset all MIDI devices, so that the new card is found.
  2. In the list of MIDI inputs tick Enable input for the entry that the norns window names (“REAPER: ENABLE VirMIDI 3-0”): Reaper lists it as hw:VirMIDI,…; the numbers follow the card and device that aconnect -l shows.
  3. Set a track’s input to MIDI > that device > All channels, arm the track, and play from a script: the notes reach the track.

The module is gone after a reboot unless you keep it. As admin copy the two example files that come with the package: /usr/share/doc/verdandi/examples/verdandi-virmidi.modules-load.conf to /etc/modules-load.d/verdandi-virmidi.conf (loads snd-virmidi at boot), and verdandi-virmidi.modprobe.conf from the same folder to /etc/modprobe.d/verdandi-virmidi.conf (options snd-virmidi midi_devs=1: one port in Reaper’s list instead of four). The package does not install them by itself, because a package should not load kernel modules or add MIDI ports to every DAW unasked.

Grids and arcs. The virtual grid (64, 128 or 256 keys), arc and keyboard open with F6, F8, F7 or their buttons, from any window. Real grids and arcs are found on plug-in; the package installs a udev rule so your user may open them. A grid is listed once.

Settings and files

Everything Verdandi makes is in your norns home, ~/Verdandi (another place: write it as the first line of ~/.config/verdandi/home). The settings files are plain key=value lines and can be edited by hand; a bad value falls back to its default with a line in the log.

dust/your scripts (code), audio, data. Clean up never touches it
ui.confSCREEN: brightness, preset, colour, contrast, and the file-dialog tick
screen-presets/your SCREEN presets, one small file each
box.conf, box-presets/THEME: style, pixel look, colours, the page buttons shown or hidden; your looks
midimap.conf, midimap-presets/MIDI MAP: mappings, actions, master switch; your presets
screen-window.confthe screen window: out or docked, place, size, fullscreen, frame
audio.confsound: see below
logs/norns.log, sclang.log, maiden.log, jackd.log, launcher.log; the last four runs are kept as norns.1.log … norns.4.log, so the log of a crash survives the restart
logs/crash/one file per crash (signal, thread, backtrace); the last 5 are kept
disabled/, backups/, cache/what Verdandi moved aside for you (with a manifest to put it back), backups before it moves anything of yours, and a cache that is safe to delete

Environment: NORNS_HOME (the norns home), NORNS_AUDIO_SERVER (auto, jackd or pipewire), NORNS_JACK_DRIVER (dummy for silence), NORNS_MAIDEN_PORT (default 5000).

If something goes wrong

Look first in ~/Verdandi/logs/norns.log (and sclang.log for SuperCollider). The note on the window names the problem.

what you seewhat to do
“GRID: serialosc has this grid” (or grid events late, wrong, twice, or no grid)serialosc is running as a service and holds the grid’s port. Stop it: sudo systemctl stop serialosc.service (start it again later with start), then replug the grid. SYSTEM > DEVICES > SERIALOSC does the stop for you after one question, if your system allows it. The note goes away by itself. serialosc_check=0 turns the check off
“PLUGINS: wrong-architecture plug-in”, or “SUPERCOLLIDER FAIL” and no engines (wrong ELF class in sclang.log)a script installed SuperCollider plug-ins built for the Raspberry Pi (32-bit ARM); they cannot load on a PC and stop SuperCollider. SYSTEM > CLEAN UP > ARM PLUG-INS moves them to disabled/, then restart. Such a script’s engines that need them will not run
“SUPERCOLLIDER: class problem” on the window; sclang.log has “duplicate Class found” or “Class … not found”the line in norns.log names the class, the folder and the likely cause. A class that SuperCollider could not find (often MiPlaits and other mi-UGens classes) means the pack is not in ~/Verdandi/.local/share/SuperCollider/Extensions/mi-UGens: restart norns, check logs/launcher.log and that mi_ugens=0 is not set. Classes found twice mean the same pack twice (a script fetched its own copy next to Verdandi’s): SYSTEM > CLEAN UP > CLASSES moves the extra copy to disabled/, then restart. If a Raspberry Pi mi-UGens pack is the problem, the PLUGINS line says so in plain words and ARM PLUG-INS moves it away; Verdandi’s own pack is copied at the next start
“DUPLICATE ENGINES” on the screen, no enginestwo files with the same name ending in .sc exist under dust (an engine installed in two script folders) and SuperCollider cannot start with both. The pairs are listed in norns.log: delete one of each pair (maiden or your file manager) and restart
A SynthDef “build failed” in sclang.logVerdandi uses SuperCollider 3.14, which refuses a few things 3.13 accepted. The log names the SynthDef; the cause is in that script or mod
“AUDIO: not connected”, or no soundno card was found or the name in in_ports / out_ports matches nothing: see SYSTEM > AUDIO. If jackd cannot open the card, PipeWire holds it: start without NORNS_JACK_DRIVER (norns then uses PipeWire)
norns closed by itselfa crash report is in ~/Verdandi/logs/crash/ and the log of that run is logs/norns.1.log; keep both when you report it
The maiden page says “not connected to norns”norns was started with --terminal: matron’s prompt is your terminal then, and nothing listens on port 5555 for maiden’s console. Start without it
“maiden is not running” / port 5000 in usestart with NORNS_MAIDEN_PORT=5001 verdandi
A script says sudo or apt is needed, or asks for a Raspberry Pi toolonly sudo systemctl restart norns-... is answered (norns restarts); other Raspberry Pi commands fail or do nothing
“ERROR grid key: …” on the windowa script’s own grid key handler failed. norns goes on and the log has the line grid key handler error with the file, the line and the traceback. If pads stay silent, load the script again, and send the log to the script’s author
The first start is slowSuperCollider starts and reports its engines before scripts load

To clear old logs and files see SYSTEM > CLEAN UP. Not yet tested on real hardware in every setup: sound cards, grids, arcs and crow, Wayland: docs/port/HARDWARE-CHECKLIST.md lists what is checked.
